# Responsiveness
## Purpose
Make pointer response, scrolling, and route entry smooth and snappy while preserving the current art direction and motion branding. The user authorized a pre-change checkpoint and bounded implementation on 2026-10-01. Lower resource counts are useful only when they improve the experience; they are not acceptance criteria.
## Constraints
Preserve live halftone, trails, physical route choreography, timings, typography, and decorative motion. Retain prepared DOM and compositor surfaces when that avoids cold entry. Do not trade background savings for a visible hitch when a section returns. Preserve reduced-motion behavior and destination-first transition handoff. Route choreography's existing visual QA remains separate.
## Starting Evidence
The latest deployed artifact is retained under `.releases/static/20261001T204005Z-4d0cb271d2d0/public/`. It is pinned against automatic release pruning. Its homepage and entry JavaScript were verified against production. The automated findings suggest repeated layout reads and background work, but resource estimates and score changes do not establish a visible regression. Browser/engine differences also prevent treating the historical report as a controlled comparison.
## First Investigation
The four homepage heading fields measure each letter after global pointer movement and scrolling, including headings far outside the viewport. Investigate avoiding that distant geometry work with generous preparation distance, while keeping the same visible calculations, easing, markup, and layers. Resume before entry rather than mounting on visibility. Leave continuous CSS decoration and GPU surfaces intact in this first pass.
## Validation
Compare the retained baseline and candidate static artifacts in the same browser with the same viewport and input sequence. Record geometry calls and main-thread work separately from frame intervals; counters alone do not prove perceived smoothness. Exercise rapid deep scrolling, re-entry, reduced motion, and route return. Reject a candidate that introduces delayed visible response or changes the design. Store scripts and raw evidence under ignored `temp-ref-assets/responsiveness/`.
## Checkpoint
The first commit carrying `Spike: responsiveness` records the untouched application plus this plan. Find it with `git log --grep='Spike: responsiveness$' --reverse`. Production remains the retained baseline until an explicitly authorized deployment.
## Candidate Mechanics
Cache heading proximity with an IntersectionObserver using a generous 1,500px band. Pointer frames keep the original easing but skip letter reads and repeated reactive publications for distant headings. Keep all markup, CSS animation, and compositor hints. On scroll, resize, or transition completion, synchronously recheck a distant heading before scheduling its update so a large jump does not wait for an observer notification.
## Rejected First Attempt
A synchronous parent-bound check on every pointer frame reduced distant letter reads and preserved visible transforms, but timings were mixed when headings were nearby. Those extra hot-path reads were removed. The initial patch and alternating browser runs remain in the ignored evidence directory; resource/call-count improvements alone were insufficient to keep it.
## First Candidate Results
Matched desktop runs preserve all 77 letters, visible transforms, CSS animation names, promotion hints, and the first three frames after direct heading re-entry. At the top, letter reads decrease from 11,550 to 1,800 over 150 pointer frames. A directly instrumented pair measures approximately 146.6ms versus 25.2ms of heading callback work, about 0.8ms of saved work per input frame in that run. Whole-page timings remain noisy and mixed; this does not establish a general FPS or production speedup. Final desktop samples contain no intervals above 25ms. Phone touch and reduced-motion states match the baseline and retain zero letter reads.

The existing structural checker passes case-study round trips on both artifacts. Latest Writing produces identical forward source-card shell and Back nav flags on both artifacts, with no page errors. These are baseline findings, not a newly identified regression from this candidate; the report does not claim every route check passes. Source checks and targeted formatting pass, with two existing lint warnings. Evidence, exact source snapshots, scripts, retained candidate, and comparison assertions live in `temp-ref-assets/responsiveness/2026-10-01/`. Human feel review remains open, and production is unchanged.
## User Comparison
On 2026-10-02 the user reported: “honestly I have trouble telling them apart. Neither seems worse though.” Keep the first candidate as a small verified reduction in interaction work without an apparent feel regression. This does not establish a perceptible speedup, and does not replace route choreography’s separate visual QA. Subsequent changes still need their own evidence and must preserve immediate preparation.
