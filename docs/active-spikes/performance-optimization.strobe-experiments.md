Updated 2026-09-19. Read this compact decision index before proposing another experiment. The [handoff](performance-optimization.strobe-handoff.md) remains the authority for detailed evidence, constraints and chronology. Earlier entries below consolidate completed historical tests; they are not newly run experiments. A visual outcome means a user report or reviewed movie, never merely a DOM check or rAF count.

## Current Conclusion
The latest isolated Chrome153 default → CoreAnimationRenderer-disabled → default comparison produced **strobe → no strobe → strobe**, with the same profile, display confirmation, viewport, full600ms morph and eight original echoes. This supports causal dependence on that rendering-path configuration in the tested scene. It does not establish the precise faulty Chromium stage or provide a deployable site repair. Static and production SSR both fail; switching delivery is not a solution. Trails off remains the user-confirmed fallback.

## Before Another Test
- Assign an ID and state the unresolved question, one changed variable, preserved controls and a decision rule before requesting human work.
- Check this ledger for a prior result. A repeat needs a named reason: replication requested by the user, a materially changed implementation, or a specifically missing control. Label it as a repeat.
- Validate mechanics offline or in a background browser first. A hidden/in-app browser pass cannot establish normal-Chrome built-in-display smoothness.
- Save raw evidence and provenance under the ignored diagnostics directory; append the outcome here promptly. Keep phase-level human verdicts separate from individual flights and from automated screening counts.
- Do not repeat the blur pair, constant-opacity candidate, canvas candidate unchanged, promotion hints, readiness patches or default/off/default experiment merely because an older paragraph still says “pending.” Latest ledger dispositions control test scheduling.
