# Reading And Browsing Interaction Polish
## Background
Promoted from the user's 2026-09-20 QA report while reviewing the performance preview. Reading text and clickable card content were advertising the wrong cursor, and a writing post opened directly could not use the shared-element return to its Home card.
## Intended Behavior
Selectable article list text/headings and testimonial quotations use the text-selection cursor. Entire-card links, including case-study excerpts/headings, Latest Writing dates and writing archive content, use the hand cursor. Preserve selection behavior, real link semantics and the lightbox's more specific zoom cursor.

Writing detail → Home should use the existing full shared-element transition whenever that post actually appears in Latest Writing, regardless of prior navigation history. Posts absent from Home use ordinary page navigation. Static clients consult the generated Home payload, never local WordPress. Failed membership lookup falls back without stranding clones. Hover/focus may prepare the membership data; clicking must also work without either.
The construction notice belongs only to a direct homepage load without a section fragment. Internal navigation and browser Back must never remount it; its existing dismiss/scroll behavior remains. Client-only eligibility avoids static HTML briefly showing it for a fragment URL.

This is interaction correctness, not a new animation design. Preserve the accepted title coherence repair, full dimensions/crop/corners, canvas trails and destination-first handoff. ## Writing Flight Image Readiness
Archive thumbnails remain small, but their loaded `currentSrc` is not sufficient for a hero-sized flight. Warm a bounded set of visible heroes and prioritize actual pointer/focus intent. Choose a decoded responsive hero before lifting and keep that texture stable throughout the morph. A bounded click-time wait shares the source-exit preparation; failed or very slow images use the loaded thumbnail fallback rather than stranding navigation. Do not turn archive browsing into eager downloading of every full-size image. Cacheable static media is required for reliable reuse of a prepared URL.

## Live Halftone Prototype
The user explicitly requires a fixed on-screen dot size while the image changes size, crop and shape. Do not derive live spacing from baked master dimensions. A successful live mode must remain live on cards, the flying photo, echoes and the landed hero; switching back to baked images during ordinary navigation is rejected. S49/S50 are superseded flight-only approximations, not the desired visual model. Use the existing CSS screen/multiply, blur/threshold and soft-K treatment as the appearance reference rather than generic subtractive CMYK. Preserve native text, full geometry/corners and reduced-motion behavior. Prototype continuously rendered surfaces before judging handoff fidelity, then measure Retina responsiveness and GPU cost. Unsupported/lost contexts need an explicit coherent fallback; no performance or fidelity claim follows merely from successful WebGL draws.
