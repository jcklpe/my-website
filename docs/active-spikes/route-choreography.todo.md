# Route Choreography — Tasks
## Background
Split from the interaction-polish spike on 2026-09-23, at the Astra → Opus 5.5 handoff. Scope and settled rules are in `route-choreography.md`. The interaction spike's history (S31–S59 previews, evidence under ignored `report/performance-optimization/diagnosis/`) stays with its archived docs.
## General Principles
- One defect per slice. Record `corepack pnpm check:transitions` output before and after each fix.
- Verify in the real generated static build and keep the previous preview running as a control.
- Transition motion only. The live halftone renderer belongs to the performance spike.
- The check judges structure and people judge feel. Do not call a visual fix done on check output alone.

## Done
- Add one repeatable round-trip check before building new route pairs (approved 2026-09-23). **Outcome:** `scripts/check-transition-journeys.mjs`, run as `corepack pnpm check:transitions` and documented in `README.md`. It has no new dependencies: it drives system Chrome over `--remote-debugging-pipe`, as `bake-case-study-halftones.mjs` already does. Three journeys (case-study, latest-writing, archive) each hover, click, settle and walk Back in about 17s total. Its findings are the Current State list above, identical on repeated runs against 3090 and 3002. Two early false positives were fixed before landing: a sub-pixel sliver along a clip edge (now at least 4px on each side), and a card shell hidden by a 90%-coverage exemption. The exemption is now exact uncovered pixels, because the border ring is what a person sees vanish. An apparent "thumbnail still concealed after Back" on the archive journey disappeared once the check allowed the return ripple up to 3s; it was a timing artifact, not a bug. The check does not judge easing, colour or the renderer. Page-side sampling adds main-thread work, so do not use it for frame-pacing claims. **Refined 2026-09-24:** the original pop rule exempted anything moving, so an exit the page swap interrupted mid-motion went unreported. That hid a whole class of defect (see the correction on the portrait entry). The check now reports `cut-short` when a moving element is hidden while still on screen with more than 34ms (two frames) of scheduled motion left, reading remaining time from the element's and its ancestors' finite animations. The two-frame grace matters because the snappy ease-in covers most of its distance in the last frame or two; Latest Writing siblings are hidden with under two frames left and read as finishing, which matches the user's acceptance of those surroundings.
