## One worthwhile optional experiment
**Delay offscreen Writing organism initialization until it is useful.** `ArticleMarginOrganisms.vue` positions patches starting well below the initial viewport and mounts `HomeReactionDiffusionBackground` with `paused` set. That component still calls `setup()` on mount, creating a WebGL2 context and linking five programs before its paused state governs ongoing simulation. The comparison traces attribute roughly 100 ms to the patch-placement callback and resulting component setup; they do not isolate the exact share of each GPU API call.

A bounded experiment could initialize a patch shortly before it approaches the viewport, preserving its reserved geometry and visual design. Compare the existing and changed build on Writing entry and the first scroll to those decorations. Keep it only if entry work decreases without a new scroll hitch, late appearance or simulation discontinuity. Do not move the same cost into the user's next scroll and call that a win. This is an analysis recommendation, not an implemented change, promised saving, required closeout item or new QA assignment.

The prototype's preload-all-five GPU policy is a weaker lead: it differs from the bounded current cache, but repeated flights already passed visual QA, and first-use timing varied between samples. No broad GPU prewarming change is recommended on that evidence. Likewise, initial hydration was complete before the sampled interactions; making the application “more static” is not supported as the next remedy.

## Deferred Writing margin experiment — 2026-09-26
The user requested this optional experiment after the initial closeout. `ArticleMarginOrganisms.vue` now keeps its existing empty patch geometry but mounts GPU children only within one viewport of the visible area, after route choreography settles. It prepares one patch per timer task (32 ms spacing), keeps mounted patches for return scrolling, prunes removed placements, and resets initialization when the narrow layout removes the patches. The existing visibility observer still pauses offscreen simulation; Home's background and the shared GPU renderer are unchanged. Scheduling spreads synchronous work; it cannot guarantee a shader compile fits every device's frame budget.

The preserved accepted static artifact is served separately on 3092; the candidate remains on 3002. In the initial isolated two-round-trip comparison at 1726×923/DPR2, control Writing entry created eight patch contexts and had 119–123 ms long tasks (106–113 ms longest attributed script), while the candidate created one context and had no entry or sampled scrolling long tasks over 50 ms. The remaining seven contexts were created progressively on descent, with no recreation on return scrolling. A final readiness/responsive run found no visible-but-unready patches across 501 candidate scroll frames; narrow mode had zero patch elements and returning to desktop mounted one of eight planned patches instead of all eight. That readiness run overlapped the GPU correctness probe, so its timing is not used as performance evidence. A subsequent isolated final-build repeat (`comparison.json`) confirmed 118/121 ms control entry long tasks versus none over 50 ms in candidate entry or scrolling; the largest attributed candidate entry script was 22.5 ms.

Validation: `corepack pnpm check`, public-CMS preview generation and preview-mode `inspect:static` pass. The default GPU trail checker passes all four journeys with no page errors or failures. Existing About/Now lint warnings remain. Evidence and the retained control are under ignored `report/performance-optimization/deferred-margins/`. These are local desktop samples, not physical smoothness certification or proof that a fast jump/slow device can never reveal a late patch. Human QA remains: enter Writing, scroll normally down and back, and confirm that margin decorations appear naturally without a new hitch or pop. No extra interruption campaign, CMS mutation, deployment or push.
