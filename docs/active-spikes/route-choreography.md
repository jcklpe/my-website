## Purpose
Make route changes physical. Shared elements (the case-study or writing photo plate and title plate) fly between card and detail; everything else on the outgoing page leaves by moving, and the incoming page arrives by moving. The generic full-page fade stays as the fallback for routes that have no designed sequence.

This spike was split out of the interaction-polish spike on 2026-09-23, when that spike closed. It owns transition motion only. Completed integration of the live halftone renderer is recorded in the archived performance spike (`docs/archive/performance-optimization.live-halftone.md`). Motion work must not depend on the renderer, and renderer work must keep this spike's round-trip check green.
## The Contract In One Paragraph
Nothing that is visible should stay still and then vanish, and nothing should pop out of existence in a single frame, unless the flying clone covers exactly that area at that moment. Surroundings leave the frame completely before the page swaps. Card shells either fade out almost immediately on click or become the traveling plate. In designed sequences, text moves through slits (a stationary clip with moving opaque ink) and does not fade. `corepack pnpm check:transitions` checks this contract mechanically; human QA judges feel, easing and timing.

## How To Verify
`corepack pnpm check:transitions [--origin=http://127.0.0.1:3002] [--width=1512] [--height=945] [--journey=case-study,latest-writing,archive] [--json]` drives system Chrome headless over the DevTools pipe. It hovers and clicks a real card, walks Back, and reports:
- any painted element of the outgoing page that is still visible and has not moved when it disappears (`still-then-vanished`), or has moved but is still on screen (`exit-incomplete`);
- any element that goes from visible to gone in one frame without moving, counting only the bounding-box area the flying clone does not cover (`popped`);
- any moving element hidden in place while still on screen with more than two frames of its scheduled motion left (`cut-short`): the page swap interrupted its exit. The snappy ease-in covers most of its distance in the last frame or two, so a swap landing inside that window counts as finishing;
- a transition that does not settle, a stranded clone layer, a destination heading that is not fully shown, a source card still concealed 3 s after Back, and page errors.

It measures visible area through clipping ancestors, so slit exits register as leaving rather than popping. Card shells are judged by uncovered bounding-box area, because a shell's border ring is the part a person sees vanish. It does not judge easing, timing feel, colour or the renderer. Run it against a fresh static build (`corepack pnpm generate:preview`, or `static:generate` plus `static:preview`) before asking for human QA, and add a journey to it before building each new route pair.

Prefer verifying in the real generated build. Injected prototype servers (the S-series) were useful for isolating renderer questions, but they fake media and scripting, so they cannot certify motion in the delivered site.
The checker does not prove that a card's uncovered box still contains painted decoration after its border, background and shadow have faded. The Latest Writing shell warning persists despite accepted static appearance; record it as a tooling discrepancy, not a reason to reopen that visual fix. Likewise a nav disappearing at the route swap is a choreography finding to discuss, not proof of broken navigation.

## Brightness-weighted dither dissolve — 2026-10-06
The user rejects the smooth lateral oscillation: it resembles an image shaking its head rather than a glitch. The new priority is a dithered fade, preferably brightness-relative like a gradient-mapped dissolve, consistent with the zine/Xerox/early-display direction. Replace the wobble, tracking crops, blur and chromatic animation with a stationary ordered transparency dissolve. The image’s colors stay authored; its luminance controls when its pixels join the visible dot pattern. This is a dithered coverage/alpha treatment, not permanent palette quantization of the photo.

A fixed 4×4 Bayer tile uses 2 CSS px cells. Reveal rank is `0.45 × (1 − luminance) + 0.55 × Bayer threshold`: brighter areas emerge first, while the stable dot pattern prevents whole tonal regions from simply popping on together. Entry increases progress from zero to one; departure reverses it. For a static image, each pixel changes visibility once per direction, so density evolves without random flicker. The original image reaches full coverage and then loses the temporary filter. Existing stagger, route clocks, text decryption, Conway handoff, lightbox controls, cancellation and reduced-motion bypass remain.

The native SVG graph derives brightness from SourceGraphic, tiles a tiny internally generated SVG pattern, computes the rank in alpha, thresholds it, and masks the unchanged SourceGraphic. Computing the rank in alpha avoids arithmetic RGB/premultiplied clamping changing the threshold. Only the coverage bias animates natively; there is no JavaScript image-pixel read, per-frame loop, shader dependency, remote pattern request, or image movement. Actual native filter paint cost and browser appearance remain unmeasured while browser access is blocked. Dot size, brightness weighting and highlight-versus-shadow priority are local visual tuning choices.
